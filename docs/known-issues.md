# Known Issues

Some bugs cannot be fixed due to the firmware in the hardware:

- the fan curve size is what `auto_points_size` reports: the number of points the EC actually uses, up to 10, and it varies by model and power mode. On models using EC fan-curve access it can be written to resize the curve, and the driver clears the points beyond the new size. On fixed-length curves (WMI3, EC2, EC3) the attribute stays read-only, as noted below. Independently of the size, a point can still be disabled by setting its temperature limits to 127
- on models using the WMI3 fan table (LPCN family, e.g. Legion Pro 5 16ARX8 / Legion 7 Pro 16ARX8H, and the EC 0x5508 generation: Legion 7 16IAX10 83KY/RXCN, Legion 5 16IAX10 83NX/Q6CN, Legion 5 15IAX10 83F0/S2CN, Legion Pro 5 16AFR10 83F2/RECN, Legion R9000P AFR10 83F6/RECN, Legion 5 15AKP10 83F1/RYCN, Legion 5 15AHP10 83M0/RGCN, Legion Pro 5 16IAX10 83F3/Q6CN, Legion Y7000P IRX10 83NN/S9CN, Legion Pro 7 16AFR10H 83RU/SMCN, Legion 5 15IRX10 83LY/QNCN, Legion 7 15ASH11 83V9/UACN, plus the Q7CN/RLCN/83LU models above), the WMI method only transmits the fan **speed** of each curve point: temperature thresholds, the second fan's speed and accel/decel values are not readable or writable through WMI (they read back as 0). On these WMI3 models the speeds are fan **levels 1-10**, not percentages - writing percent values into the level bytes matches the thermal-shutdown reports for these models, so the module exposes only the speed attributes and treats them as levels. The EC keeps using its own firmware temperature thresholds. The speed-only layout was confirmed on the Legion Pro 5 16ARX8 (BIOS LPCN65WW), the level unit by DSDT analysis across the 0x5508 chassis (issue #491); for the LPCN family see the next item. [#140](https://github.com/johnfanv2/LenovoLegionLinux/issues/140)
- on the LPCN family (Legion Pro 5 16ARX8 / Legion 7 Pro 16ARX8H, EC 0x5507) and the Legion Slim 7 16IRH8 (82Y3, BIOS M0CN, same EC; [#637](https://github.com/johnfanv2/LenovoLegionLinux/issues/637)) the fan table also takes **levels**, not the percentages older module versions wrote: the firmware copies the ten bytes unchecked into the EC like on the Intel KWCN models, publishes a 10-level RPM ladder, and Lenovo Legion Toolkit refuses values above 10. On a Legion Pro 5 16ARX8 with BIOS LPCN59WW, writing 50 (an older module's "50 %") into point 1 **hard-powered-off** the laptop about 6 s later. The module now reports `level` for LPCN. A level table (1..10) written on that LPCN59WW unit drove the fans to the firmware ladder RPM without problems, but other LPCN BIOSes are untested, so fan curve **writes stay disabled** by default. The EC also only accepts tables **at or above** that default (1..10): in custom mode, lower values are reset at once, so a custom curve can only make the fans louder; for quiet use `low-power`. Writes fail with `EPERM` unless the module is loaded with `allow_unvalidated_fancurve=1`. legion_cli, legion_gui and legiond refuse speeds above level 10 when an older module still reports `percent` on LPCN firmware. A table written by an older module or legiond can still hold bytes above 10 (`dmesg`: `above level 10 (stale percent write?)`); see [LPCN verification](FEATURES_AND_TESTING.md#legion-pro-5-16arx8-82wm-lpcn) before writing anything.
- on level-based WMI curves, GUI/CLI RPM requests are rounded to firmware levels and clamped to the driver's per-point minimum, including zero-RPM requests. Native RPM curves, including R3CN's EC3 curve, retain zero-RPM support and are not quantized to WMI levels. The read-only `fancurve_speed_unit` attribute identifies the active curve's unit (`rpm`, `percent` or `level`); firmware RPM ladders are exposed only for level curves, independently of default-curve reset support. Userspace refreshes calibration for every read/apply operation; percentage backends also round-trip their percentage steps without losing speed through double rounding. Missing or invalid calibration blocks RPM writes instead of guessing a linear scale; the GUI keeps monitoring available and offers Read from HW to retry. Update the module and userspace together for explicit unit detection.
- on Legion 5 15AHP11 (83Q7, T2CN), the WMI curve uses shared **levels**, not percentages. Its SFAN write and RPM calibration use the live thermal mode, not the saved power-profile request; writes/default resets are rejected in extreme mode or when the mode cannot be read. Firmware RPM tables retain zero-RPM and repeated entries at their original indices; dropping a leading zero shifts the speed mapping. See [T2CN firmware evidence and verification](FEATURES_AND_TESTING.md#legion-5-15ahp11-83q7-t2cn).
- fan-curve fields are exposed according to the implemented access method, not the EC chip ID. EC2 preserves CPU/GPU temperatures and eight points and EC3 preserves all temperature fields; neither has programmable accel/decel. All WMI3 curves expose only the shared speed table. The GUI disables individual unsupported fields without disabling supported temperatures. Fixed-length curves report a read-only `auto_points_size`. Unmapped minifancurve/controller-lock registers are never accessed. See [capability checks](FEATURES_AND_TESTING.md#fan-curve-capability-and-unit-checks).
- on the Legion Pro 5 16ARX8 (BIOS LPCN65WW), the firmware's `max-power` mode **cuts power instantly** (hard power-off with no shutdown sequence) instead of raising limits, and can also reset the EC battery charge mode from conservation back to rapid charge. The kernel module therefore does not expose `max-power` as a platform profile choice on this model; the safe profiles are quiet/balanced/performance/custom.
- on the Legion 5 Pro 16IAH7H (82RF, BIOS J2CN), the firmware only enters `custom` on AC. On battery it keeps running balanced and remembers the request until AC is plugged in, and while it does, its own mode read reports `custom`, even after a later `balanced` request. The kernel module therefore refuses `custom` on battery on this model (`EOPNOTSUPP`), and reports that remembered state as `balanced`, which is what the EC runs. A request left over from older module versions or from unplugging AC while in custom still switches to custom when AC comes back; Fn+Q clears it. [#651](https://github.com/johnfanv2/LenovoLegionLinux/issues/651)
